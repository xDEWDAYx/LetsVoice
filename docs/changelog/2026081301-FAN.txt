1. 【基础设施】样式改动不热更新 / 窗口白屏
------------------------------------------------------------------------
问题：
  - 改了 CSS 后 npm start 仍显示旧样式，需反复重启才生效。
  - 修复上述问题后，Electron 窗口打开即白屏，标题停留在
    electron-react-boilerplate。

原来：
  - 两个 dev webpack 配置均未设置 watchOptions，完全依赖 Windows 原生文件
    监听事件；外部工具/编辑器的原子重命名写入经常被漏掉，webpack 不重编译。

现在：
  - renderer 与 main 的 dev 配置均加入轮询监听：
      watchOptions: { poll: 1000, aggregateTimeout: 300, ignored: ... }
  - 关键点：main 配置的 ignored 必须排除构建产物目录
      ignored: /node_modules|[\\/]dll[\\/]/
    否则轮询会把 webpack 自己写出的 .erb/dll/tsconfig.tsbuildinfo 误判为源码
    变化，形成「重编译 → 写产物 → 再次触发」的死循环，electronmon 不断重启
    Electron，窗口在 bundle 就绪前被反复加载，表现为永久白屏。
  - renderer 侧无此问题（产物在内存中，不落盘）。
  - 修复后日志验证：renderer file change 与 app exited 均归零。

  涉及文件：
    .erb/configs/webpack.config.renderer.dev.ts
    .erb/configs/webpack.config.main.dev.ts

2. 【优先修复】录音停止后弹窗被推理阻塞
------------------------------------------------------------------------
问题：
  - 点击停止录音后，需等全部转录与语义整理跑完，复核弹窗才出现。

原来：
  - stopRecording() 中依次 await session.stop() 与
    transcription.finalizeLiveSummary()，弹窗调用排在这一整串之后。
    finalizeLiveSummary 内部还要依次等待转录队列、总结队列，并再跑一次
    evaluateSemanticBuffer（真正的 LLM 推理）。

现在：
  - 顺序调整为：stop() 之后立即开窗，finalizeLiveSummary() 放到后台执行。
  - 配套把弹窗内容从「打开瞬间的冻结快照」改为实时快照 transcriptionSnapshot，
    转录与总结结果陆续回填。仅调顺序不改数据源的话，弹窗会秒开但内容永远为空。
  - 新增进度反馈：标题下方转圈「正在整理…」，内容区显示「正在转录…」
    「正在生成…」，替代原先误导性的「未生成语义总结」。
  - 数据安全：saveAsNote 内部本就会先 await finalizeLiveSummary 再读快照，
    因此整理未完成时点保存也不会丢内容。

  涉及文件：
    src/renderer/pages/Studio/StudioPage.tsx
    src/renderer/pages/Studio/components/RecordingReviewDialog.tsx
    src/renderer/pages/Studio/StudioPage.css

9. 检索改为关键词 + 向量混合（RRF 融合）
------------------------------------------------------------------------
问题：
  - 原实现是串行降级：只要关键词命中一条，语义检索就永远不会执行。
    字面命中但语义更相关的笔记因此没有出场机会。

原来：
  - keyword 命中 → 直接返回 match: 'keyword'；
    完全没命中才调用 embedding，返回 match: 'semantic'。

现在：
  - 两路都执行，再用 RRF（Reciprocal Rank Fusion）融合排序：
      score = Σ 1 / (60 + 该路名次)
    选择 RRF 是因为关键词匹配只有「命中/未命中」没有分数，与余弦相似度
    不可比；RRF 只依赖名次，且同时被两路命中的笔记会累加得分自然排到前面。
  - 返回结果附带 match 字段（keyword / semantic / keyword+semantic）与
    similarity 余弦分数，便于模型判断可信度。
  - 语义检索失败时静默降级为纯关键词，并附带 semanticUnavailable 说明，
    不会因为向量模型缺失导致整体报错。

  代价（已知）：
  - 每次搜索都会调用一次 Ollama 做查询向量化，首次还需批量 embed 笔记
    （之后按内容 sha256 缓存）。当前为全量线性扫描 + 200 条索引上限，
    笔记量大幅增长后需要考虑向量索引。

  涉及文件：

    src/main/agent/__tests__/AgentSearchNotesTool.test.ts（新增）

11. CSS 优先级引发的三个显示 Bug
------------------------------------------------------------------------
这三个 Bug 同源：页面级/容器级存在 `.类名 元素` 形式的宽泛规则
（优先级 0,1,1），会压过单类名的小图标按钮规则（0,1,0）。

(1) 复制图标不显示
  - `.studio-page button` 强加 padding: 0.5rem 0.8rem，而 `.copy-button`
    仅设 width: 28px；border-box 下左右内边距吃掉 25.6px，内容区仅剩约 2px，
    16px 图标被挤到不可见。朗读按钮因用两级类名 `.tts-play-control
    .tts-play-button`（0,2,0）而幸免。
  - 改法：CopyButton 外层加 .copy-control，样式改用两级类名。

(2) 「最近会话」文字消失、加号异常
  - `.ask-ai-recents button` 是后代选择器，把标题行里的＋也匹配进去，
    强加 width: 100% 使其独占整行，把标题文字挤成零宽。
    工作区那几行因使用子选择器 `.ask-ai-note-group > button` 而幸免。
  - 改法：改为 `.ask-ai-recents-list > button` 精确作用域；
    ＋按钮统一改用两级类名书写以防复发。
  - 同时将 details/summary 结构换为普通 h3 标题行（去掉 ::marker 干扰），
    标题与＋置于同一容器。

(3) 中文标题竖排
  - 中文无词边界，可收缩的 flex 项 min-content 宽度等于一个字宽，被压缩时
    会逐字换行成竖排。
  - 改法：标题 span 加 flex: 1 1 auto; min-width: 0; white-space: nowrap;
    text-overflow: ellipsis，空间不足时截断而非竖排。

(4) 笔记库列被压扁（同批修复）
  - `.ask-ai-note-list` 缺少 flex-grow（默认 0 1 auto，只收缩不伸展），
    撑不满剩余高度；而「最近会话」用 flex: 0 0 auto + max-height 34% 死占位。
  - 改法：笔记列表 flex: 1 1 auto 吃掉剩余高度并内部滚动；最近会话改为
    flex: 0 1 auto、上限 32%；笔记行内边距收紧，小窗口可多显示条目。

  涉及文件：
    src/renderer/components/CopyButton.tsx / .css
    src/renderer/pages/AskAI/AskAIPage.css
    src/renderer/pages/AskAI/components/AskAINotesPanel.tsx
