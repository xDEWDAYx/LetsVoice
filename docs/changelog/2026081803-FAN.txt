1. 【BUG-001 / P2】Jest 测试启动即失败
------------------------------------------------------------------------
问题：
  - npm test 直接失败，无法作为 CI 质量门。
  - 报告记录的是 1 个 suite 失败；实测为 5 个。

原因（共四条，报告只覆盖了第一条）：

  a. window.electron 缺失
     Jest 跑在 jsdom 里，没有 Electron preload 注入的 window.electron。
     ModelRecommendationController 的构造函数默认参数直接读
     window.electron.recommendation，在 import 阶段就抛
     "Cannot read properties of undefined"。
     注意报告里的定位已经过时：顶层 singleton 已从 ModelManagerPage.tsx
     迁到 useModelManager.ts:20，但问题性质不变。

  b. WorkspaceDetailHeader 的 props 类型与实参不符
     onRename / onDelete 声明为 (): Promise<void>，而 WorkspacePage 传的
     是同步的 setShowRenameModal(true)，ts-jest 编译期即报 TS2322。
     这两个回调只是开弹窗，本来就不该是异步的。

  c. WorkspaceNoteCard 读了一个契约里没有的字段
     渲染子笔记徽标时用了 subnote.template_name，而 WorkspaceService 里
     subnotes 的查询只 SELECT 了 id / content_type / content / created_at，
     该字段从来就不存在。运行时永远走 fallback 显示 'Sub-note'，
     类型检查则直接报错。

  d. jest 把其他会话的工作树也收了进来
     .claude/worktrees/ 下有三份旧副本，其中的 App.test.tsx 各自因为
     自己那份代码的编译错误而失败，与主仓库无关。

修复：
  - 新增 .erb/scripts/jest-setup-electron.ts，作为 setupFiles 统一提供
    window.electron 替身：用 Proxy 兜住任意命名空间与方法，普通方法返回
    Promise，onXxx / offXxx 同步返回取消订阅函数（与 preload 真实签名一致），
    少数会被解构或遍历的接口在 defaultResults 里登记结构完整的默认值。
    同时补上 jsdom 没实现的 matchMedia、ResizeObserver、IntersectionObserver。
  - useModelManager.ts 里的模块顶层 new 改为组件内部 useMemo，
    preload 未注入的环境不会再在 import 阶段崩溃。
  - WorkspaceDetailHeader 的两个回调类型改为 (): void。
  - WorkspaceNoteCard 去掉 template_name，直接渲染 'Sub-note'。
    这与修改前的实际显示完全一致，没有行为变化。
  - package.json 的 jest 配置加 testPathIgnorePatterns / modulePathIgnorePatterns
    排除 <rootDir>/.claude/。

结果：
  npm test 从 5 failed / 11 passed 变为全部通过，exit code 0。

涉及文件：
  .erb/scripts/jest-setup-electron.ts（新增）
  package.json（jest 配置）

  src/renderer/pages/Workspace/components/WorkspaceDetailHeader.tsx

2. 【BUG-002 / P3】Lint 失败
------------------------------------------------------------------------
问题：
  - 报告记录 161 项；实测已恶化到 1901 项（1874 error + 27 warning）。

处理分三步。

  第一步：npm run lint:fix
    1901 → 180。绝大多数是 prettier 格式。

    此处有一个必须记住的坑：eslint 的 import/no-relative-packages 规则会
    把 .erb/configs/webpack.config.base.ts 和 .erb/scripts/electron-rebuild.js
    里的 '../../release/app/package.json' 自动改写成包名形式
    'speakspace-app/package.json'。release/app 并不是已安装的依赖，改完
    直接把 lint 自己跑崩（TS2307）。已改回相对路径并加定向 disable 注释。
    今后再跑 lint:fix 要留意这两处。

  第二步：规则层面关掉 5 条，每条都在 .eslintrc.js 里写了理由
    - no-undef 对 *.ts / *.tsx 关闭
      这是报告里 "NodeRequire is not defined" 的根因。TypeScript 自己会
      检查未定义标识符，而 no-undef 认不出 NodeJS / NodeRequire / globalThis
      这类 ambient 类型，在 TS 文件里必然误报。这也是 typescript-eslint
      官方的建议做法。
    - import/prefer-default-export 关闭
      本项目统一用具名导出，仓库里原本散着 14 处 inline disable 专门压它。
      关掉规则后这些 disable 一并删除，是净收益。
    - react/require-default-props 关闭
      React 19 已不再在运行时读取 propTypes，可选属性由 TS 类型表达。
    - react/jsx-props-no-spreading、react/function-component-definition 关闭
      纯风格，与本项目既有写法冲突。
    另外两条按规则自带的选项调整而非关闭：
    - promise/catch-or-return 加 { allowFinally: true }
      本项目习惯 .catch(...).finally(...) 收尾。
    - jsx-a11y/no-noninteractive-tabindex 加 { roles: ['separator'] }
      可拖动分隔条是 ARIA 的 window splitter，本来就必须可聚焦。

  第三步：其余 86 条逐条改代码，包括
    - 9 处 button 缺 type
    - 9 处未使用的变量 / 导入
    - 16 处 a11y（div + onClick 改成语义 button，见下方回归说明）
    - 11 处 hooks 依赖缺 t
    - 2 处 import 循环（StudioPage ⇄ StudioChatPanel，
      新增 StudioTypes.ts 承载共享类型打断）
    - class-methods-use-this、no-plusplus、prefer-destructuring、
      no-useless-escape、no-return-await、default-param-last、
      no-nested-ternary、no-template-curly-in-string 等

顺带删除两处确认无人引用的死代码（报告 BUG-002 建议里点名了第一处）：
  - src/main/ipc/recording-ipc.ts
  - src/main/Recording/TranscriptionService.ts
    这个文件除了无人引用，里面还有一句
    require('../database/entities/Note') —— 该目录根本不存在
    （实体在 src/main/entities/），真跑到那行必然抛错。
    现役实现是 src/main/transcription/ 下那一套。

结果：
  npm run lint exit code 0。剩 23 条 no-console warning，都是主进程与
  错误分支里的有意日志，warning 不阻断退出码，本次未动。

3. 【BUG-003 / P1】Fresh install 后 Electron binary 不完整
------------------------------------------------------------------------
报告的猜测是「下载或解压在 postinstall 阶段失败」。实测根因不同，
而且已在本机完整复现：

  Windows 上只要还有进程在跑 node_modules/electron/dist/electron.exe
  （典型情况：上一次 npm start 的开发实例没关），该进程就锁住了 dist 里的
  resources.pak、locales 等文件。此时 Electron 的 install.js 往已存在的
  dist 上覆盖解压，会**静默失败**——extract-zip 的 promise 既不 resolve
  也不 reject，进程直接以 0 退出；fs.rmSync(dist) 则报 EPERM，并且
  已经删掉的文件不会回滚。

  于是留下一个「缺可执行文件的半成品 dist」，而 npm install 照样 exit 0。
  用户要到 npm start 才发现应用起不来，报错看上去和依赖毫无关系，
  重跑 npm install 也修不好——这正是报告里「需要手动解压 Electron zip」
  的成因。

修复：
  - 新增 .erb/scripts/check-electron-binary.js，挂在 postinstall（在
    electron-builder install-app-deps 之后）和 prestart 上，另提供
    npm run check:electron 手动调用。
  - 完整性判据：path.txt、dist/version、当前平台可执行文件三者齐备，
    且可执行文件大小非 0（解压中断会留下 0 字节占位文件）。
  - 检测到不完整时先探测是否有 Electron 进程占用（win32 走 tasklist，
    其余走 pgrep）：
      有占用 → 不做任何破坏性操作，直接报告是谁占着，并给出
               taskkill /F /IM electron.exe /T && npm install
      无占用 → 清空 dist 后重跑官方 install.js，仍不完整则给出
               rm -rf node_modules/electron && npm install
               以及镜像设置命令，并以非零码退出。

验收：
  报告给的验收命令（rm -rf node_modules && npm install && npm start）
  需要重装全部依赖，本次未执行。已验证的是：脚本在正常环境下 exit 0；
  在人为删除 electron.exe 且有进程占用的情况下，能正确识别占用者、
  拒绝执行破坏性删除、并以非零码退出。

      macOS：检查钥匙串里的 Developer ID Application，或 CI 注入的

7. 【回归】日历日期格变成绿色胶囊按钮
------------------------------------------------------------------------
现象：
  仪表盘日历里每个日期格都变成一颗实心绿色胶囊，整块整块的，
  与页面完全不搭。

原因：
  App.css 有一条全局规则 `button { ... }`，给所有 button 上了主色渐变、
  胶囊圆角、1.6rem 内边距和白色文字。第 2 节修 a11y 时，把
  div + onClick 改成了语义 button，这些元素立刻被该规则接管。
  .calendar-day 自己只设了 border-radius 和 padding-top，没有背景色，
  原设计是透明格 + 悬停浅色 + 今天蓝底 + 有待办时下方两个小圆点。

  同一次改动共有 6 处中招，只是日历最显眼：
    - 日历日期格、日历弹层里的待办条目
    - 仪表盘「置顶笔记」「待办」两张指标卡
      （文字变白、左对齐变居中、悬停动效被按钮的顶掉）
    - Dashboard / Studio / Workspace 三处右键删除菜单

修复：
  没有逐个打补丁，而是让全局按钮样式支持退出：
    button:where(:not(.btn-plain)) { ... }
  用 :where() 包住否定条件，选择器权重保持 0-0-1 不变——这点是关键，
  否则页面里几十处用 class 覆写按钮样式的写法会集体错位。
  再加一个 .btn-plain，只清掉浏览器默认按钮外观，最终长相仍由元素
  自己的 class 决定。button:focus-visible 对所有按钮保留，包括
  .btn-plain——这些元素改成 button 本来就是为了键盘可达。

  另外顺手把日历网格的 key 从数组下标改成了「年-月-日期」结构：
  原先用 weekIdx / dayIdx 做 key，换月时会跨月复用节点。
  改成在构建网格时就给每个单元格算好稳定 key。

涉及文件：
  src/renderer/App.css
  src/renderer/pages/Dashboard/components/CalendarWidget.tsx
  src/renderer/pages/Dashboard/components/MetricCardsGrid.tsx
  src/renderer/pages/Dashboard/DashboardPage.tsx
  src/renderer/pages/Studio/StudioPage.tsx
  src/renderer/pages/Workspace/WorkspacePage.tsx

8. 已下载的模型不会被自动选中
------------------------------------------------------------------------
问题：
  首次进入页面时，模型明明已经下载好，系统却不会自动选中它。
  因为没选中，对话工作台的开工前检查一开始就报「未安装或未选择模型」。

原因：
  「已下载」和「已选中」是两件独立的事。模型文件在硬盘上，但
  userData/model-state/*.json 里没记 id 时，三个 ModelManager 的
  getModelList() 一个都不标 activated。

修复：
  - ActiveModelStateStore 新增 resolveActiveModelId(downloadedIds)：
    已保存的选择仍在已下载列表里就沿用，否则挑目录里第一个已下载的
    并落盘。STT / TTS / LLM 三个 manager 的 getModelList() 统一走它。
  - 顺带修好「删掉当前模型后剩下的那个不会被自动接上」。

  一处必须留意的陷阱：
    LLMModelManager.getInstalledModelNames() 在 Ollama 没起来时会
    catch 掉错误并返回空集合。如果照直处理，Ollama 一掉线就会把用户

10. 模型管理页下拉被后面的卡片遮挡
------------------------------------------------------------------------
问题：
  点开左上角 STT 的下拉，列表会被下面 Embedding 整个模块盖住。

原因：
  不是 z-index 不够大。.model-module 上有 backdrop-filter，
  **该属性会创建层叠上下文**，卡片内部 .model-select-list 的
  z-index: 20 只在自己这张卡片里排序，跨卡片比较时完全不参与，
  于是后面的卡片按 DOM 顺序整块盖上去。

修复：
  - .model-module 补 position: relative + z-index: 0，
    给卡片之间一个可比的层级基准。
  - .model-module:has(.model-select-list) { z-index: 10 }，
    在下拉真正展开的那一刻把整张卡片抬起来，收起立刻回落。
    列表是条件渲染的（{open && <ul>}），所以这个选择器天然精确，
    不需要改任何 JS。

  页面上所有下拉（STT / TTS 模型 / TTS 音色 / Embedding / LLM）用的都是
  同一个 ModelSelect 组件、装在同一种 .model-module 卡片里，一处修完
  全部生效。已搜过整个 renderer，绝对定位的下拉列表只有这一个组件。

涉及文件：
  src/renderer/pages/ModelManager/components/ModelModule.css

1. 【重要】维护者本机的旧笔记数据没有被迁移过来

   第 4 节的 userData 迁移在本机执行得不完整。
   %APPDATA%/SpeakSpace/.userdata-migrated 记录的 copied 列表是：
       app-settings.json / blobs / runtimes / models / output

       %APPDATA%/electron-react-boilerplate/speakspace.db   114688 字节（旧数据）
       %APPDATA%/SpeakSpace/speakspace.db                    65536 字节（空库）

   成因有两条，都是迁移实现本身的问题：
     a. 改名和迁移不是同一次落地的。改名后 electronmon 自动重启了一次
        应用，DatabaseManager 先建出了一个空库；等迁移代码加进来时，
        copyIfMissing 看到目标已存在就跳过了——而数据库恰恰是最该迁的
        那一个。
     b. MIGRATED_ENTRIES 是写死的白名单，漏了 model-state，
        今后应用新增任何 userData 目录也都会被漏掉。
        正确做法应该是「排除 Chromium 自己的缓存目录，其余全拷」。

   模型和运行时目录是完整的（已逐字节比对：388 个模型文件 6.58 GB、
   108 个运行时文件 2.17 GB，两边文件数与总字节数完全一致），
   所以功能可用；缺的是笔记、工作空间、对话这些库内数据。

   建议：修正迁移逻辑（改为排除式 + 目标已存在时先备份再覆盖），
   并把本机旧库手工接回。本次未擅自改动 userData 下的任何文件。

       因为开发实例正开着；关掉再跑即可。
     - electron-builder 解压 winCodeSign-2.6.0.7z 需要创建符号链接，
       报「客户端没有所需的特权」，需要开 Windows 开发者模式
       或以管理员身份运行。
