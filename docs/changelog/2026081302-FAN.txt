1. 【环境】机器上同时跑着两套实例，样式看起来「有两个版本」
------------------------------------------------------------------------
问题：
  - 启动后用户发现界面样式与之前测试时不同，怀疑存在两个版本。

原来：
  - 进程列表里同时存在两组 webpack/electronmon：
      · simplify-text-use-icons-542fef worktree（代码为 017a1e4）
      · app-startup-test-9647c9 worktree（代码为 babb771）

现在：

    十余分钟的 npm install（两边代码同为 babb771，依赖完全一致）。
  - 统一清理所有 speakspace 相关的 node/electron 进程后再启动，
    保证任意时刻只有一个实例在跑。

  说明：
    后续每次改动主进程或 preload 都需完整重启 npm start——preload 的
    webpack 配置是一次性构建，不在 watch 列表里；只改 renderer 时
    dev server 会自动热更新，无需重启。

6. 【硬件检测】显卡识别失败与 CUDA 展示
------------------------------------------------------------------------
问题：
  - 设置页硬件面板显示「显卡：未检测到」，但机器上确有独立显卡。
  - 本地推理很依赖 CUDA，需要显示其可用性。

原来：
  - 仅使用 Electron 的 app.getGPUInfo('basic')。该接口在 Windows 上返回的
    deviceString 常为空字符串（只有 vendorId / deviceId），取到空即判为
    未检测到。这不是硬件问题，是检测手段单一。

现在：
  - 新增 GpuProbeService，多路探测后合并取信息最全的一条：
      1) nvidia-smi     —— 优先级最高，给出真实显存、驱动版本、CUDA 版本
      2) WMI（Win32_VideoController）—— Windows 通用路径，覆盖 A 卡与核显
      3) system_profiler / lspci —— macOS 与 Linux
      4) Electron getGPUInfo('complete') —— 兜底，名称为空则丢弃
    每路各自 try/catch，单条命令 5 秒超时，任一路失败不影响其余。
  - 关键坑：WMI 的 AdapterRAM 是 32 位字段，超过 4 GiB 一律返回
    4293918720（4 GiB 上限）。本机实际 6144 MiB，若直接采信会显示成错的
    4 GB，故撞上限值时判为未知，显存优先取 nvidia-smi。
  - 虚拟显示适配器（GameViewer / 远程桌面 / 虚拟机一类）会被识别并标注
    「虚拟显示器」，排在真实显卡之后，且不作为主显卡参与推荐判断。
  - 新增 CUDA 行：从 nvidia-smi 表头解析版本，无 N 卡或无驱动显示「不可用」。
  - 新增存储检测：用 fs.statfs 统计模型与运行时所在分区（不扫其他盘）。
  - 设置页新增「硬件」分类：处理器、内存、显卡（多卡逐行）、CUDA、存储、
    系统，底部给出推荐档位，并有「重新检测」按钮；中英文案均已补齐。

  本机实测合并结果：
      NVIDIA GeForce RTX 3060 Laptop GPU  6 GB  驱动 591.86  来源 nvidia-smi
      GameViewer Virtual Display Adapter   —              来源 wmi（虚拟）
      CUDA 13.1 · 1 卡
      存储 474.7 GB 总量 / 27.1 GB 可用

7. 【对话工作台】笔记详情缺少摘要
------------------------------------------------------------------------
问题：
  - 双击笔记打开右侧详情时，只显示原文转录，没有摘要。

原来：
  - 预览组件只渲染 note.transcript || note.transcriptPreview。
    摘要并不在笔记列表接口里——它保存在 subnotes 表，contentType 形如
    「AI 语义总结 1 / Semantic summary 1」，列表接口不返回。

现在：
  - 新增 AskAI:getNoteDetail(noteId) IPC，返回笔记连同其 subnotes。
  - 预览面板分成两段：「摘要」（每条整理结果一张小卡，带自身类型标题）
    与「原文转录」。摘要置于原文之前——原文可能很长，摘要放下面会被埋掉。
  - 没有摘要时显示「这条笔记还没有摘要」（语义整理依赖 Ollama，
    老笔记可能本就没有存）。

  涉及文件：
    src/main/ask-ai/AskAIService.ts、AskAITypes.ts
    src/main/ipc/ask-ai-ipc.ts、src/main/preload.ts
    src/renderer/pages/AskAI/components/AskAINotePreview.tsx
