1. 【仪表板】整页硬编码繁体，设置里的语言开关完全管不到
------------------------------------------------------------------------
问题：
  - 设置里选的是「简体中文」，其它页面都是简体，唯独仪表板整页繁体：
    儀表板 / 筆記總數 / 轉錄總字數 / 待辦事項 / 沒有找到合乎篩選條件…

原来：
  - Dashboard 的四个组件里所有中文都是 JSX 里写死的繁体字符串，
    从未调用 t()，所以 AppSettingsProvider 里的 i18n.changeLanguage
    对这一页没有任何作用。
  - zh.json 里 sidebar.dashBoard 的值本身就是繁体「儀表板」，
    侧边栏那一项因此也是繁体（这一条是简繁混排的直接来源）。

现在：
  - zh.json 的 sidebar.dashBoard 改为「仪表板」。
  - 新增 50 个 dashboard.* 键，zh.json 为简体、en.json 为英文；
    两个语言文件各 126 个键，已用脚本校验键集完全一致、无遗漏。
  - 四个组件全部接入 useTranslation()，覆盖标题、按钮、卡片标签、
    tooltip、星期栏、表头、搜索占位符、空状态、排序项。
  - 词汇与全应用统一：置顶（其它页面已在用）而不是「钉选」，
    笔记（而不是「筆記」）。

  涉及文件：
    src/i18n/locales/zh.json、en.json
    src/renderer/pages/Dashboard/DashboardPage.tsx
    src/renderer/pages/Dashboard/components/HeaderBar.tsx
    src/renderer/pages/Dashboard/components/MetricCardsGrid.tsx

2. 【仪表板】笔记分类改用语言无关的 key
------------------------------------------------------------------------
问题：
  - 顺带发现的隐患：分类筛选直接拿繁体字符串当筛选值。

原来：
  - NoteListTable 里 categories = ["全部","需求評審","項目討論",…]，
    筛选逻辑是 selectedCategory === '全部' || note.getTypeCategory() === selectedCategory。
    一旦文案换语言（或后端存的是简体），比较就永远不成立，筛选静默失效。
  - 后端 DashboardService 固定返回 typeCategory: "未分類"（繁体），
    与前端列表里的任何一项都对不上。

现在：
  - 新增 DashboardCategory.ts：界面逻辑一律用 review / discussion /
    brainstorm / general / uncategorized 这些 key，显示文案交给 i18n。
  - 简繁两种历史写法（需求評審 / 需求评审 …）都归一到同一个 key，
    未知值归为 uncategorized。
  - 筛选下拉补上「未分类」一项——后端目前所有笔记都是这个值，
    不补的话这批笔记根本筛不出来。
  - matchesSearch 增加 categoryLabel 参数：搜索匹配的是用户当前
    语言下实际看到的分类文字，而不是库里那份原始字符串。

  涉及文件：
    src/renderer/pages/Dashboard/models/DashboardCategory.ts（新增）
    src/renderer/pages/Dashboard/models/DashboardNoteItem.ts
    src/renderer/pages/Dashboard/components/NoteListTable.tsx
    src/renderer/pages/Dashboard/DashboardPage.tsx

3. 【仪表板】相对时间与年月标题跟随界面语言
------------------------------------------------------------------------
问题：
  - 「今天 / 昨天」和「2026 年 8 月」写死在工具类里，切英文不会变。

原来：
  - DashboardTimeUtil.formatRelativeUpdatedTime 直接返回拼好的
    `今天 ${hh}:${mm}`；formatYearMonthDisplay 返回 `${year} 年 ${month} 月`。

现在：
  - 改为 describeRelativeUpdatedTime，只返回「是今天/昨天/绝对日期」
    的描述符（labelKey + time + absoluteText），文案由组件 t() 渲染，
    模型层保持无语言依赖。
  - formatYearMonthDisplay 接收 locale，改用 Intl.DateTimeFormat：
    zh 得到「2026年8月」，en 得到「August 2026」。

  涉及文件：

5. 【仪表板】整页横向溢出，只能靠左右滚动才能看全
------------------------------------------------------------------------
问题：
  - 用户反馈：笔记列表水平上太长，页面溢出，只能横向滚动，很难用。

原来：
  - .dashboard-page-container 上写着 min-width: max-content。
    这一句决定了整页宽度 = 表格最宽那一行的宽度，于是溢出的不是表格
    而是整个页面，横向滚动条出现在 .content-area 上。
  - .dashboard-main-content 是 460px 1fr 的网格，grid 子项默认
    min-width: auto，右列不允许收缩到内容宽度以下，表格会一直把它顶宽。
  - .td-title 又写了 min-width: 240px，表格最小宽度被进一步抬高。
  - .table-responsive 虽有 overflow-x: auto，但外层先被撑开了，
    它永远轮不到生效。

现在：
  - 去掉 min-width: max-content，改为 max-width: 100% + min-width: 0。
  - 网格改为 minmax(320px, 420px) minmax(0, 1fr)，两列都写 minmax(0,…)，
    左右列都补 min-width: 0，右列可以正常收缩。
  - 表格改 table-layout: fixed，各列给定像素宽度（合计约 400px），
    标题列吃掉剩余宽度；标题与转录摘要加省略号，不再靠撑宽来显示。
  - 窄屏按重要性依次隐藏次要列（创建时间 → 录音时长 → 类型），
    两栏布局与单栏布局用不同断点，宁可少一列也不出现横向滚动条。
  - 搜索框由固定 240px、聚焦跳到 280px，改为可伸缩（上限 280px），
    避免它在窄窗口把整行控件顶出容器。

  实机确认：页面不再横向滚动，右上角「设置 / 新建笔记」两个按钮回到可见区。

  涉及文件：
    src/renderer/pages/Dashboard/DashboardPage.css

6. 【工作空间详情】排版重构：一屏先看到笔记，而不是先看到装饰
------------------------------------------------------------------------
问题：
  - 用户反馈：样式太丑，例如搜索框为什么这么长；要求彻底重构排版，
    简约高效一点。

原来：
  - 顶部是一整块渐变 hero（圆角 26px、内边距 1.8rem、标题
    clamp 到 3.2rem），四条元信息各自是一个圆角胶囊，一屏先被标题吃掉。
  - 关键词搜索独占一张卡片：卡片里一行说明文字 + 一个 width:100% 的
    输入框——用户抱怨的「搜索框这么长」就是这里。
  - 语义搜索又是另一张整宽卡片，里面大半是空的。
  - 笔记卡片是卡中卡中卡：article(圆角22) → section(圆角16) →
    item(圆角12)，每层都有自己的背景和边框；录音单独占半格大盒子。
  - 按钮全部继承全局 button 样式（大号渐变胶囊 + 重阴影）；
    「匯出 Word / 匯出 PDF」用的是 .btn-secondary / .btn-sm，
    而这两个类只定义在 DashboardPage.css 里——没进过仪表板页
    这两个按钮就没有样式，属于跨页面的隐式依赖。
  - 多选浮条整块用内联 style 写死。

现在：
  - WorkspacePage.css 整份重写，统一一套间距 / 圆角 / 字号刻度：
      · 顶部改成一行：左标题 + 元信息，右操作；元信息用 · 分隔。
      · 关键词搜索与语义查找合并成一条工具条，搜索框 max-width 380px，
        语义查找按钮就在旁边，语义结果整行铺在下一行。
      · 笔记卡片去掉两层嵌套：区块之间只用细线分隔，不再各自套
        背景 + 边框 + 圆角；只有列表项保留浅底。
      · 录音从半格大盒子压成标题下面的一条细行。
      · 页面自带 .ws-btn / .ws-btn-primary / .ws-btn-quiet /
        .ws-btn-danger / .ws-btn-icon，不再依赖仪表板的 CSS。
      · 多选浮条内联 style 全部搬进 .workspace-select-bar。
  - 多笔记分析弹窗的内联 style 一并搬进 CSS，并顺手把里面的繁体
    （多筆記關聯分析 / 關閉 / 正在分析關聯性 / 分析失敗提示 / 发给模型的
    提问文案）改成简体——这些文案会出现在对话记录里，用户看得见。

9. 【全局】字号统一：49 种散号收敛为 7 级刻度
------------------------------------------------------------------------
问题：
  - 用户反馈：设置里有统一字号，但对话工作台、工作空间详情、模型管理
    的字明显偏小；希望统一管理，允许有层级差别，但不能差太多。

原来：
  - 全应用共有 49 种不同的 font-size 取值，从 0.62rem（约 10px）
    到 clamp(…, 3.4rem)，同一层级的文字在不同页面各写各的
    （0.62 / 0.64 / 0.65 / 0.66 / 0.68 / 0.7 / 0.72 / 0.74 / 0.75 / 0.76 / 0.78 …）。
  - 仪表板整页用 px 写死（30 处，11px～36px）。px 不跟随 html 字号，
    所以「设置 → 输出文字字号」对仪表板完全无效——用户说的
    「设置里有统一字体大小」在这一页其实一直没生效。

现在：
  - 在 App.css 的 :root 定义 7 级刻度（括号为 medium/16px 下的实际值）：
      --fs-xs   0.8rem    12.8px  角标、时间戳、次要计数
      --fs-sm   0.875rem  14.0px  说明文字、小控件
      --fs-md   0.95rem   15.2px  正文
      --fs-lg   1.05rem   16.8px  强调正文、卡片标题
      --fs-xl   1.25rem   20.0px  区块标题
      --fs-2xl  1.6rem    25.6px  页面标题
      --fs-3xl  2.1rem    33.6px  首屏大标题
  - 用一次性 codemod 把 186 处 font-size 按就近原则映射到这 7 个变量
    （rem 与 px 各一张映射表），全部改为 rem，因此仪表板也开始跟随设置。
  - 最小字号由 0.62rem 抬到 0.8rem，最大由 3.4rem 压到 2.1rem：
    极差从约 5.5 倍收敛到 2.6 倍，既保留层级又不再「差太多」。
  - 图标字号刻意不动（12 处）：.card-icon-wrapper / .star-icon /
    .empty-icon / .settings-*-glyph / .workspace-home-card-arrow 等，
    这些 font-size 控制的是图标大小而不是正文，按选择器名自动排除，
    并逐条人工复核过。

  涉及文件：
    src/renderer/App.css（新增刻度定义）
    另 17 个 CSS 文件由 codemod 批量替换

10. 【全局】codemod 把字号刻度的锚点也改坏了（自查发现并修复）
------------------------------------------------------------------------
问题：
  - 第 9 项的 codemod 是无差别扫全部 CSS 的，它把 AppSettings.css 里

  - 三行恢复为 14px / 16px / 18px，并加注释写明「这是整套 rem 刻度的
    锚点，必须保持 px」，避免以后再被同类批量替换误伤。
  - 恢复后重新截图确认：对话工作台的笔记库列表、时间戳等文字大小
    正常且明显比改动前易读。

11. 【环境】worktree 里把应用跑起来
------------------------------------------------------------------------
问题：
  - 本 worktree 没有 node_modules，直接 npm start 起不来；
    起来之后主进程又报 Cannot find module 'better-sqlite3'。

现在：
  - 用目录联接把主仓库依赖指过来（三处，都在 .gitignore 内，不进版本库）：
      <worktree>/node_modules        -> 主仓库 node_modules
      <worktree>/.erb/node_modules   -> 主仓库 release/app/node_modules
      <worktree>/src/node_modules    -> 主仓库 release/app/node_modules
    后两处是关键：ERB 把原生依赖装在 release/app/node_modules，
    主进程 bundle 位于 .erb/dll/，靠 .erb/node_modules 这个软链才能解析到
    better-sqlite3；主仓库本来就有这两个链接，worktree 里缺失。
  - 另从主仓库拷入 .erb/dll/renderer.dev.dll.js 与 renderer.json，
    避免 webpack 因缺 DLL 而触发 npm run postinstall
    （那会对共享的 node_modules 重建原生依赖，影响主仓库）。
  - 启动前先清理占用 1212 端口的残留 dev server（当时没有 electron 窗口
    在跑，只剩一个孤儿 node 进程）。
