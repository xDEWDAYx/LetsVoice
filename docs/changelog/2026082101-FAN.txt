贯穿全篇的两条经验：

  1. **看不见的样式改动等于没改**。本次有近十处「按推理写完、
     自认为对」的样式最后都是错的：类名撞车、层叠上下文没圈住、
     选择器压根选不中、滚动条占位造成的视觉偏移。后来固定成一套
     流程——把真实 CSS 内联进临时 HTML、在浏览器里渲染、用脚本量
     偏移和计算样式、截图确认、删掉临时目录——才一个个揪出来。
     文中凡标「实测发现」的，都是这套流程抓到的，靠读代码看不出来。

  2. **能跑真的就别演假的**。引导里四个演示动画，前三个是自己画的
     （拖拽、双击、浮窗），最后一个（日历联动）改成往真实元素派发
     鼠标事件、让应用自己反应。后者代码更少、永远不会和真实行为
     对不上，而且 React 改了事件合成方式测试会先红。

2. 【AI 分类】笔记不再全是「未分类」
------------------------------------------------------------------------
现在：
  转写完成后，本地模型（qwen2.5:3b-instruct）除了抽待办，再单独跑
  一次分类，落到 notes.category 字段。五个类型：
    meeting 会议 / personal 私事 / idea 想法 / learning 学习 / general 日常
  分类失败不算错误，退回「未分类」照常显示，下次还能补。

为什么单独一次调用：
  让小模型在一次回答里既抽日期又判类型，实测两边准确率都会掉。
  分类只送转写开头 1200 字——说话人往往一上来就点明场合，
  截断既省推理时间，也避免长转录把小模型带偏。

自测：
  按要求拿本地已有的 13 篇真实笔记跑了一遍准确率。
  首轮 0/13 全部落到「未分类」，排查后是解析函数的一个字面量 bug
  （见下），修完后 13/13 全部命中人工判断。
  评测脚本留下可复跑：scripts/dev/classify-eval.js
                     scripts/dev/classify-notes-check.js

  【实测发现】首轮 0/13 的原因：
    new RegExp(`\b${key}\b`) —— 模板字符串里的 \b 是退格符（U+0008），
    不是正则的单词边界。改成 String.raw 后正常。
    这个 bug 读代码时完全看不出来，正则也不报错，只是永远匹配不上。

4. 【正向】悬停日历日期 → 右边对应笔记整行闪烁
------------------------------------------------------------------------
现在：
  - 鼠标停在有圆点的日期上直接展开当天待办（不必再点一次），

  【实测发现】闪烁效果分段：

    拆成两条动画——背景色动画给所有 td，高亮条动画只给 td:first-child。

第五段  三个轻量浮窗
========================================================================

核心原则：按快捷键不打开主界面。主界面一弹出来就打断了手上的活，
而这三件事都是「瞥一眼就走」。

  统计浮窗   360×190   右下角   四个环：笔记数 / 置顶 / 待办 / 转录字数
  待办浮窗   360×300   右下角   只列今天和明天
  录音胶囊   150×52    下方居中  取消 · 波纹 · 完成

实现要点：
  - 无边框、透明、置顶（screen-saver 级）、不进任务栏，
    hash 路由 #/hud/{stats|todos|record}，与主界面共用同一个渲染包。
  - 预热常驻、关闭只是 hide 不 destroy——否则每次按快捷键要等
    将近一秒才出来。窗口重新显示时发 Hud:shown 事件，渲染层据此
    重新取数、重置淡出计时。
  - 落点是纯函数 computeHudBounds，多屏 / 缩放边界可直接测。

交互细节：
  - 待办只列今天和明天，逾期与下周不占地方；同一天同一件事去重。
  - 每条待办左边勾掉、右边置顶，都是先本地生效再落库——浮窗就那么
    几秒，等 IPC 回来再消失会让人以为点了没反应。
  - 鼠标停在浮窗上暂停自动消失，移开后重新从头计时。
  - 录音胶囊只有三件东西，不显示时长。完成后主界面自动打开，
    走平时那套转写、复核、存成笔记的流程；取消则直接丢掉。

  【实测发现】三个靠推理改不出来的样式问题：
    a. 胶囊被两个圆按钮撑得死死的，上下一点缝都没有。
       原因是类名撞车：外层窗口壳的 class 是 "hud hud-record"，
       内层那一行也叫 hud-record，于是行上的 align-items: center
       连外壳一起套上，卡片不再撑满窗口（量出来 23.6px，应为 42px）。
       内层改名 hud-record-bar 后正常。
    b. 快捷录音按停止没反应：startQuickRecord 的监听器挂在 StudioPage
       上，切到别的路由就卸载了。改成走 app 级桥接 + 路由 state。
    c. 复核弹窗的 ✕ 看着偏右：量出来偏移 0.00/0.00，真正的不对称来自
       scrollbar-gutter: stable both-edges 和原生 select 的下拉箭头。
       前者按两侧留位、后者用 appearance: none + 自绘 chevron 解决。

涉及文件：
  src/main/background/HudWindow.ts（新增）
  src/shared/hud/HudLayout.ts（新增，尺寸与落点，主/渲染共用）

18. 【动画四】联动演示：不演假的，直接跑真的
------------------------------------------------------------------------
这一个和前三个不同：它**往真实元素上派发 mouseover / mouseout**，
弹窗、列表滚动、行高亮全是应用自己被触发后做出的反应。引导只画
一个指针和一圈套住「鼠标此刻停在哪儿」的光环。

  正向（calendarTodos）：指针飞到日历带圆点的那天 → 弹出当天待办、
    右边整片相关笔记闪起来 → 移进弹窗停到第一条 → 列表滚到那篇
    笔记、收窄成只闪那一行 → 第二条 → 收手重来。
  反向（todoDateHover）：指针依次停到列表里三颗日期药丸上，
    左边日历对应的那些天闪起来。

  同一个组件，openSelector 可选：正向需要先「展开」才有条目可走，
  反向不需要，直接一格一格走。

  关键机制：React 的 onMouseEnter 不是原生事件，是根节点上
  mouseover / mouseout 配对推算的。而且如果 mouseover 的
  relatedTarget 是 React 树里的元素，React 会直接跳过，改由
  mouseout 那侧算出 leave+enter 这一对。所以从日期格挪进弹窗时
  必须先在旧目标上派 mouseout（带上新目标），日历那边取消关闭
  定时器的逻辑才走得通——否则弹窗会在指针刚进去时被收掉。

  指针飞行 520ms 之后才派事件，顺序反了就成了「指针没到、界面先动」。
  这个时长在 CSS 的 transition 和组件的 TRAVEL_MS 两处，注释互指。

  布局取舍：联动两头都要看得见，所以聚光灯罩住装着日历和笔记列表
  的整块（.dashboard-main-content）。但这样卡片没地方放——
  placeCard 的兜底是「贴着某条边居中」，正好压在弹窗上。加了第三种
  摆位 corner：钉右下角，和弹窗（贴着日历右侧展开）错开。

  z-index 故意没动：日历弹窗是 9999，比引导层的 2000 高，联动演示
  要的就是它浮在遮罩上面看得见。代价是可能压住说明卡，靠 corner 规避。

  原来 NoteListTable 上那两个 data-tour 锚点（dashboard-notes /
  dashboard-todo-column）没人引用了，一并删掉——留着会让人以为
  「这里被引导指着，别乱改」。

文件：src/renderer/onboarding/TourHoverDemo.tsx（新增）
测试：src/__tests__/TourHoverDemo.test.tsx（8 项）

  【测试里抓到的一个真问题】
    原本写「卸载时松手」，测的是 unmount() 整棵树——但那样弹窗本来
    就随页面一起没了，断言等于没测。改成只卸载演示、页面留着
    （翻页时真实发生的就是这个）之后，反向那条立刻红了：

    原因是同级卸载顺序：演示排在列表后面，列表的清理先跑，
    等演示派 mouseout 时表格已经脱离文档了。真实场景不会踩到，
