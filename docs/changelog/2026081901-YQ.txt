本次改动为笔记与工作空间增加完整的回收站生命周期：普通删除改为可恢复的
“移入回收站”，只有用户在回收站再次确认后才会彻底删除。功能覆盖工作空间、
对话工作台、仪表盘与笔记详情，并完成中英文、深浅主题、原生 SQLite、macOS
打包启动以及 Windows/macOS/Linux CI 门禁适配。


------------------------------------------------------------------------
1. 【数据生命周期】笔记和工作空间先进入回收站
------------------------------------------------------------------------
现在：
  - workspaces 与 notes 增加可空的 trashed_at 字段；旧数据库启动时原地迁移，
    NULL 表示正常内容，时间戳表示已进入回收站。
  - 删除单篇笔记只写入回收站时间，不改正文、置顶、创建时间、更新时间、
    子笔记、知识输出、待办或录音引用，恢复后仍是原记录。
  - 删除工作空间前显示确认框；确认后工作空间及其全部笔记作为一个回收站
    项目移动，恢复时一起恢复。
  - 普通工作空间、笔记、仪表盘、待办、语义建议和 AI 上下文查询全部排除
    回收站内容，避免已删除内容继续出现在正常工作流中。
  - 回收站内容无限期保留，不做自动清理。

涉及文件：
  src/main/database/DatabaseManager.ts
  src/main/database/repositories/*.ts
  src/main/trash/TrashService.ts（新增）
  src/main/ipc/trash-ipc.ts（新增）
  src/shared/types/TrashTypes.ts（新增）

2. 【设置】新增回收站入口、搜索、筛选、恢复与彻底删除
------------------------------------------------------------------------
现在：
  - 设置左侧分类顺序为“外观、语言、智能助理、硬件、回收站、使用引导”，
    回收站位于硬件与使用引导之间。
  - 回收站支持按名称、笔记正文和原工作空间搜索，并可筛选全部、笔记或
    工作空间；分类入口显示项目数量角标。
  - 恢复立即生效，并可跳转查看恢复后的工作空间或笔记。
  - 彻底删除必须在独立确认框再次确认；确认文案明确说明不可撤销。
  - 彻底删除笔记会级联清理附属内容和无引用的托管录音；历史 AI 对话与
    消息保留，只移除已失效的笔记关联，避免删除超出用户确认范围的数据。
  - 操作成功与角标刷新分离；即使后续角标刷新失败，也不会把已经成功的
    恢复或删除误报为失败。

3. 【各页面入口】常驻垃圾桶、开盖动画、确认框与撤销
------------------------------------------------------------------------
现在：
  - 对话工作台笔记库、仪表盘笔记列表、工作空间笔记卡片均使用统一的
    TrashCanButton；垃圾桶常驻显示，鼠标悬浮或键盘聚焦时仅桶盖打开。
  - 对话工作台笔记卡片的垃圾桶固定在右下角，按钮盒子与 SVG 始终居中；
    最终将按钮下移到日期/时间所在水平线，悬浮时不再错位或消失。
  - 删除笔记后从当前列表和已关联来源中移除，并显示 5 秒撤销入口；撤销后
    恢复原笔记及当前页面需要的选择、预览与关联状态；撤销请求仍在执行或
    返回错误时会暂停自动关闭，避免操作尚未结束提示就消失。
  - 删除工作空间保留删除前确认；确认框宽度收紧为 400px、自适应高度，
    不再继承多笔记弹窗的 70vh 固定高度。
  - 工作空间确认框的“取消/确认”补齐正式中英文词条，不再在中文界面出现
    英文 Cancel。

5. 【跨平台与 CI】真实 Electron ABI 回归进入三系统矩阵
------------------------------------------------------------------------
现在：
  - 回收站实现使用 Electron、React、SQLite 参数化查询和 ISO 时间戳，没有
    增加 darwin/win32 分支、平台路径拼接或平台专属系统 API。
  - better-sqlite3 安装的是 Electron ABI；普通 Node Jest 无法加载时会明确
    跳过，新增 test:trash:electron 由 Electron 的 Node 模式真实执行全部
    回收站数据库测试，避免把“跳过”误报为“通过”。
  - GitHub Actions 的 macOS、Windows、Ubuntu 矩阵均执行 package、lint、
    TypeScript、test:trash:electron 与全量 Jest；推送后由真实 Windows runner
    负责 NSIS 打包和原生 SQLite 验证。

涉及文件：
  package.json
  .github/workflows/test.yml
  src/main/trash/__tests__/TrashService.test.ts（新增）
