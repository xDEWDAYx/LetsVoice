1. 【优先修复】停止录音后不再等待全部推理完成才打开复核弹窗
------------------------------------------------------------------------
问题：
  - 点击「停止录音」后，界面需要等待最后一段音频转写、语义总结等推理全部
    完成，才显示复核弹窗；用户会误以为停止按钮没有生效。

原来：
  - stopRecording() 依次等待 engine.session.stop() 与
    engine.transcription.finalizeLiveSummary() 完成；
  - 只有全部 await 完成后，才调用 openReviewFromSnapshot() 打开弹窗。

现在：
  - 点击停止后立即把复核弹窗置为打开状态，并标记为「正在整理录音」。
  - 使用 requestAnimationFrame + 一个事件循环让弹窗先完成绘制，再继续执行
    停止录音、收尾转写和语义总结，确保用户能立即得到可见反馈。
  - 弹窗保持挂载，在最后一段转写与总结结果陆续到达时自动刷新原始转录和
    整理文本，不再出现“先空白等待、最后才弹另一个窗口”的体验。
  - 整理期间禁用关闭、重新录制与保存，避免录音会话仍在收尾时被错误打断；
    收尾完成后自动恢复操作。
  - 增加停止请求防重入保护，避免用户连续点击停止导致重复收尾或重复弹窗。

  涉及文件：
    src/renderer/pages/Studio/StudioPage.tsx
    src/renderer/pages/Studio/StudioPage.css
    src/renderer/pages/Studio/components/RecordingReviewDialog.tsx

2. 模型管理页面重构为四个清晰模块
------------------------------------------------------------------------
问题：
  - 原页面混合展示模型、运行时状态、推荐、能力检测、模型列表等多个区域；
    同一个概念被拆成多个面板，阅读路径凌乱、文字过多。
  - STT runtime、FFmpeg 可用性等被拆成独立选项卡/面板，占用空间且不利于
    快速做模型选择与比较。

原来：
  - 页面分别展示 Whisper、Parakeet、Ollama、TTS、Embedding、推荐模型等
    多种面板；STT 与 LLM 另有独立的模型列表。
  - 推荐理由、运行时状态和模型操作分散在页面不同位置。

现在：
  - 页面收敛为仅四个模块的 2 × 2 布局：
      STT（语音识别） / TTS（语音合成） /
      Embedding（向量检索） / LM（大语言模型）。
  - 每个模块只保留一个模型选择入口；当前状态、推荐状态和模型操作均在该模块
    内完成，不再单独展示“大段推荐说明”“本机能力已配备”等重复文字。
  - 顶部只保留「全部在本机运行」这一轻量状态提示，减少页面噪声。
  - 模型管理页会统一刷新模型、运行时、Embedding 和本机推荐状态，操作结束后
    自动同步界面。

  涉及文件：
    src/renderer/pages/ModelManager/ModelManagerPage.tsx
    src/renderer/pages/ModelManager/ModelManagerPage.css
    src/renderer/pages/ModelManager/components/ModelModuleCard.tsx（新增）
    src/renderer/pages/ModelManager/components/ModelModuleCard.css（新增）

3. 富信息下拉选择框：用 UI 与图标代替文字墙
------------------------------------------------------------------------
问题：
  - 原生下拉框只能显示纯文本模型名称；用户选择或对比时看不到大小、语言、
    引擎、量化、参数规模、速度等关键信息。
  - “未下载”“已下载”“推荐”“当前”等状态依赖文字，信息密度低且视觉冗余。

原来：
  - 模型详情、下载/删除按钮与模型选择入口分离。
  - 用户要先选择模型，再跳转或查看其它区域才能理解模型差异。

现在：
  - 以自定义、可访问的下拉组件取代浏览器原生 select。
  - 收起状态直接显示当前模型的模型名，以及大小、语言、引擎、格式/量化等
    最关键的四项信息。
  - 展开状态中，每个模型选项直接显示：
      大小、语言、引擎、格式/量化、参数规模、速度。
    TTS 同时显示参数量、采样率与实时能力；Embedding 显示语言、引擎、类型、
    用途和本地运行状态。
  - 推荐模型改为星标图标；当前启用模型改为勾选图标。
  - 未下载模型仅显示下载图标；已下载模型仅显示删除图标；下载或删除进行中
    显示加载动画。图标保留 aria-label/tooltip，兼顾无障碍与可理解性。
  - 下拉支持点击外部关闭、Esc 关闭与方向键展开；弹层覆盖显示，不会撑乱
    原有四模块布局。
  - 点击已下载的 STT / LM 模型即可切换激活；点击未下载模型的下载图标会按需
    安装运行时、下载模型并自动激活。

  STT 模型信息规则：
    - Parakeet：0.6B / 极速；
    - Whisper Tiny / Base / Small / Medium / Large：分别显示对应规模与
      最快 / 快 / 均衡 / 精确 / 高精度；
    - 自动识别 INT8、Q5 等格式。

  LM 模型信息规则：
    - 直接显示模型大小、语言、Ollama 引擎、量化格式；
    - 从模型名识别参数规模（例如 1.5B、3B），并以参数规模推导
      极速 / 均衡 / 高质量的本地运行定位。

  涉及文件：
    src/renderer/pages/ModelManager/ModelManagerPage.tsx
    src/renderer/pages/ModelManager/components/ModelModuleCard.tsx
    src/renderer/pages/ModelManager/components/ModelModuleCard.css

4. TTS 与 Embedding 补齐删除能力
------------------------------------------------------------------------
问题：
  - 用户希望模型下拉中，已下载项目统一有删除图标；原项目的 TTS 与
    Embedding 只有安装能力，缺少对应的删除动作。

现在：
  - TTS：新增删除受应用管理的 Kokoro 模型目录和 manifest 的能力；安装进行中
    不允许删除，且删除前验证路径必须在应用受管目录中。
  - Embedding：新增通过 Ollama 删除 bge-m3 模型的能力；删除前确保 Ollama
    服务已运行。
  - 删除 STT、LM、TTS、Embedding 均会要求用户确认；删除后自动刷新状态。
  - 删除 TTS/Embedding 模型不会删除用户录音、笔记或工作区数据。

  涉及文件：
    src/main/tts/TTSRuntimeInstaller.ts
    src/main/semantic/OllamaEmbeddingService.ts
    src/main/ipc/runtime-ipc.ts
    src/main/ipc/semantic-ipc.ts
    src/main/preload.ts
    src/renderer/pages/ModelManager/ModelManagerPage.tsx
