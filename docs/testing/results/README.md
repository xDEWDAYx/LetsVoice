# 这个目录是什么

`docs/testing/results/` 是所有评测脚本的原始输出。这份 README 只回答一个问题：
**打开这个目录，为什么有些文件平铺在最外层，有些在 `machines/<标签>/` 里？**

## 两层结构

**顶层平铺的 JSON**——每个脚本自己写的地方，不分机器。这里面混着两种东西：

- **准确率类**（待办提取、Agent、检索质量、逐模型调优消融……）——这些**永远只在这里**，
  不会也不需要进 `machines/`。它们取决于模型和提示词，不取决于硬件，只在主控机跑一次，
  当前这些报告引用的就是这批数据：[test-coverage-gaps.md](../test-coverage-gaps.md)、
  [datasets/](../datasets/README.md) 里说的"跨机器不会变"指的就是这批。
- **硬件相关类**（TTS 速度/内存、LLM 吞吐、STT 转写速度）——每次**直接**运行对应脚本
  （比如手动跑 `npm run bench:tts`）都会覆盖这里的同名文件。这是"这台机器最近一次跑出来的
  暂存结果"，不代表按机器整理好的对比数据。

**`machines/<机器标签>/`**——按机器归档的干净快照，只包含硬件相关类的文件。
**`npm run bench:aggregate`（跨机器对比表）只读这里，完全不看顶层平铺的文件。**

## 正常使用不需要关心这个区别

只要都用 **[一键入口](../multi-machine-benchmark-guide.md)**（`npm run bench -- --machine <标签>`
或者根目录的 `一键跨机硬件测速.cmd`），跑完会自动把这一轮真正测出来的硬件相关文件
复制进 `machines/<标签>/`，跑之前就躺在顶层、这一轮没碰过的旧文件不会被误收进去。

跑完你只需要拷 `machines/<标签>/` 这一个子文件夹去汇总，顶层那堆不用管、不用删、
也不用弄懂它们分别是什么——它们要么是不分机器的准确率数据（本来就该留着），
要么是这台机器自己的暂存输出（下次在这台机器上跑什么都会覆盖它）。

这个区别只有在**手动**分别跑单个脚本（而不是走一键入口）时才需要弄清楚——
比如开发调试某个脚本的时候。当前顶层这批硬件相关文件（`tts-*.json`、`llm-runtime.json` 等）
就是开发过程中手动跑出来的，不代表已经归档好的机器对比数据。
