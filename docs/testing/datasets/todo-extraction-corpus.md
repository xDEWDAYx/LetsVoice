# 待办提取语料：54 条

机器可读源文件：[todo-extraction-corpus.ts](../../../scripts/benchmark/todo-extraction-corpus.ts)

每条用例是一段模拟真实语音转写后的口语化文本，配一份金标：应该抽出哪几条待办、
每条的截止日期、是否重复、有没有绝不该出现的日期（数字干扰项）。评测脚本
（[todo-extraction-scoring.ts](../../../scripts/benchmark/todo-extraction-scoring.ts)）
拿模型的抽取结果跟金标比对，算 Precision / Recall / F1 / 日期准确率 / 假阳性率。

评测基准时间固定为 **2026-08-20 14:30（周四）**，所有"明天""下周三""这周末"这类相对日期
都按这一天推算，跟 `RelativeDateRewriter.ts` 的规则保持一致，方便复现。

## 开发集 22 / 保留集 32

| 子集 | 条数 | 用途 |
| --- | --- | --- |
| dev（开发集） | 22 | 调提示词期间反复看过、改过。分数偏乐观，只作回归基线 |
| holdout（保留集） | 32 | 提示词定稿之后才写，定稿后未再调整。是泛化能力的真实证据 |

## 19 个场景标签

| 场景 | 条数 | 场景 | 条数 |
| --- | --- | --- | --- |
| 假阳性（不该抽出任何任务） | 8 | 隐晦任务 | 5 |
| 绝对日期 | 4 | 相对日期 | 4 |
| 周期任务 | 4 | 多任务 | 3 |
| 边界 | 3 | 委婉语气 | 3 |
| 任务归属 | 3 | 无日期 | 3 |
| 模糊时间 | 2 | 提醒日 | 2 |
| 去重 | 2 | 中英混合 | 2 |
| 极短输入 | 2 | 口语改口 | 1 |
| 完成状态 | 1 | 长文本 | 1 |
| 同日多任务 | 1 | | |

**假阳性**是最大的一类（8 条），专门测模型会不会把陈述句、已完成事项当成新任务抽出来——
这类错误在真实使用中比漏检更让人反感，一条误报的待办比一条漏掉的待办更容易被用户注意到。

## 示例（各取一条，其余见源文件）

**D01 · 绝对日期**
> 九月四号上午十点我要去参加那个供应商的评审会，地点在三号楼会议室。

金标：1 条，关键词 `评审/供应商/会`，截止 `2026-09-04`；禁止出现 `2026-08-03`、`2026-09-03`（数字干扰项）。

**D14 · 假阳性**
> 今天的会主要是同步一下上半年的情况。营收比去年同期涨了百分之十二，华东区表现最好，华南稍微差一点。人员方面没什么变动，就这些。

金标：0 条任务。这是纯陈述句，没有任何待办语义。

**H01 · 绝对日期（保留集）**
> 2026年9月1日要交年度预算的初稿，九月十五号之前完成部门述职材料。

金标：2 条，`预算/初稿` → `2026-09-01`；`述职/材料` → `2026-09-15`。

**H03 · 相对日期（保留集）**
> 这周末抽空把家里的路由器换了，顺便把宽带续费也办了。

金标：2 条，`路由器` → `2026-08-22`；`宽带/续费` → `2026-08-22`（同一天两件事，测是否会漏抽其中一条）。

## 历史：这不是从零构造的

更早有一版 22 条纯手写、只有散文描述、没有机器可读金标的验收用例。现在这 54 条
（含开发集/保留集拆分、关键词与日期金标、场景标签）是在那版基础上重写扩充的，
旧版已不再单独保留，内容已被这份语料完全取代。

## 已知局限

- 输入是**干净文本**，不含语音识别错误；真实链路的输入是转写结果，可能带错字、断句错误。
  真实表现预期比本语料上的数字更差，这项测试还没有做。
- 不是公开数据集，构造者对场景覆盖有主观选择，可能遗漏了真实用户会遇到的表达方式。
- 假阳性场景样本量（8 条）不足以精确估计误报率的置信区间，只能做方向性判断。
